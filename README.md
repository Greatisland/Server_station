# MIG Station (server-control)

서버 컴퓨터가 재부팅되어도 **아무나 로그인만 하면 관리 화면(스테이션)이 자동으로 뜨고**,
전문지식 없이 **브라우저에서 딸깍 클릭으로 서버를 켜고 끌 수 있게** 해주는 도구입니다.

> 서버 자체는 자동으로 켜지지 않습니다. 스테이션이 뜬 뒤 **[켜기] 버튼을 눌러야** 시작됩니다.
> (잘못된 설정으로 서버가 무한히 재시작되며 수정 불가에 빠지는 일을 막기 위한 정책입니다.)

- 새로 설치되는 프로그램(exe) 없음 — 이미 설치된 node.exe와 브라우저만 사용합니다.
- 관리자 권한 불필요 — 서비스 등록 없이 사용자 시작프로그램만 이용합니다.

## 최초 설치 (담당자가 서버 컴퓨터에서 1회)

1. `스테이션 열기.cmd` 더블클릭
2. 끝. 브라우저에 MIG Station 페이지가 열리고, 바탕화면에 **[서버 상태]** 아이콘이 생깁니다.

`스테이션 열기.cmd`는 설치 전용이 아니라 **언제 실행해도 안전한 만능 버튼**입니다.
실행할 때마다 자동시작 등록을 갱신하고, 스테이션이 닫혀 있으면 열고, 상태 페이지를 띄웁니다.
뭔가 이상하면 일단 이걸 다시 실행하면 됩니다.

설치되면 이후에는:
- 재부팅 → 아무 계정이나 로그인 → 스테이션(관리 화면)이 자동 실행됨
- 서버는 자동으로 켜지지 않습니다 — 관제 페이지에서 **[켜기]** 로 직접 시작하세요.
- 서버가 죽어도 자동으로 다시 켜지지 않습니다 — 상태만 🔴로 표시되며, 원인 확인 후 수동으로 다시 켜면 됩니다.
- 스테이션·서버·빌드 전부 **창 없이 백그라운드로** 실행됩니다. cmd 창이 뜨지 않는 게 정상입니다.

## 일반 직원 사용법

바탕화면의 **[서버 상태]** 아이콘을 더블클릭하면 MIG Station 페이지가 열립니다.

| 표시 | 의미 |
|------|------|
| 🟢 초록 카드 (ON AIR) | 켜짐 — 정상 작동 중 |
| 🟡 노랑 카드 | 켜는 중/준비 중/끄는 중 — 기다리면 됩니다 |
| 🔴 코랄 카드 | 꺼짐 → **[켜기]** 버튼 클릭 |

- **켜기 / 끄기 / 재시작**: 버튼 클릭 → 확인 → 끝.
- **업데이트 적용**: 코드를 새로 받은 뒤(git pull) 이 버튼을 누르면 다시 빌드하고 재시작합니다.
- **로그**: 문제가 있을 때 담당자에게 보여줄 화면입니다.

## 서버 추가/수정 (다중 서버)

MIG Station 페이지 하단 **[⚙ 서버 설정]** 에서 서버를 여러 개 등록할 수 있습니다.

| 항목 | 설명 | 예시 |
|------|------|------|
| 서버 이름 | 화면에 표시될 이름 | `MigManager` |
| 실행 폴더 | 절대경로 또는 이 폴더 기준 상대경로 | `D:\Migmanager` 또는 `..` |
| 실행 명령어 | 서버를 켜는 명령 | `npm run start` |
| 포트 | 서버가 실제로 여는 포트 (상태 감지 기준) | `3737` |
| 확인 방식 | `http`(기본) 또는 `tcp`. Postgres처럼 HTTP를 안 말하는 포트는 `tcp` | `tcp` |
| 빌드 명령어 (선택) | [업데이트 적용] 시 실행할 명령 | `npm run build` |
| 빌드 확인 파일 (선택) | 이 파일이 없으면 시작 전 빌드부터 실행 | `.next/BUILD_ID` |

설정은 `servers.config.json`에 저장됩니다. (직접 편집했다면 스테이션 재시작 필요)

## 문제 해결

- **MIG Station 페이지가 안 열려요 ("연결 끊김")**
  → 스테이션이 닫힌 상태입니다. `스테이션 열기.cmd` 더블클릭.
  (이 경우에도 이미 켜 둔 서버 자체는 계속 돌고 있습니다 — 관제 화면만 멈춘 것)
- **스테이션(서버 관리)을 잠깐 닫아두고 싶어요**
  → MIG Station 페이지의 **⚙ 서버 설정 → [서버관리 종료]**. 서버는 그대로 두고 관리 화면만 닫힙니다.
- **"시작 실패" 빨간불**
  → 카드의 [로그] 버튼 → 실행/빌드 로그에서 원인 확인. 로그 파일은 `logs\` 폴더에 있습니다.
- **"포트가 응답 없는 프로세스에 점유됨"**
  → [끄기]를 눌러 정리한 뒤 다시 [켜기].
- **개발할 때 주의**: `npm run dev`도 3737 포트를 쓰므로, 이 컴퓨터에서 개발하려면
  먼저 MIG Station 페이지에서 서버를 끄고 dev를 띄우세요.
- **재부팅 후 스테이션(관리 화면)이 안 떠요**
  → 로그인은 했는지 확인하세요. 잠금화면(로그인 전) 상태에서는 시작프로그램이 실행되지 않습니다.
  (스테이션이 떠도 서버는 자동으로 켜지지 않으니, 페이지에서 **[켜기]** 를 눌러야 합니다.)

## 제거

도구를 완전히 걷어낼 때(담당자용): 서버 컴퓨터의 `server-control` 폴더에서 `node setup.mjs --remove` 실행
→ 시작프로그램 등록과 바탕화면 아이콘이 제거되고 스테이션도 닫힙니다. (이미 켜져 있는 서버는 그대로)
실수 방지를 위해 이 기능은 화면 버튼으로 제공하지 않습니다.

## 파일 구성

```
server-control/
├─ watchdog.mjs          스테이션 본체 (관제 API + 상태 감시)
├─ control.html          MIG Station 페이지 UI
├─ servers.config.json   서버 목록 설정
├─ run-hidden.vbs        창 없는 실행 런처 (스테이션이 서버를 띄울 때 사용)
├─ setup.mjs             등록/해제/중지 로직
├─ 스테이션 열기.cmd      유일한 실행 파일: 등록 갱신 + 스테이션 열기 + 상태 페이지 표시 (반복 실행 안전)
└─ logs\                 실행/빌드/스테이션 로그
```
